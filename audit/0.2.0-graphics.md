# venti 0.2.0 graphics audit status

## scope and current baseline

The repository package is still version `0.1.0`. The current graphics path is
`pty reader -> GraphicsParser -> pane vt100 parser / PaneGraphicsStore -> core
layout and screen update -> client apply_update -> host terminal`. Query
responses are generated by `QueryResponder` and written to the pane PTY master.
The client advertises terminal identity in the hello; `outer_term` maps that
identity to a graphics protocol.

The `GraphicsParser` owns stream framing and Kitty chunk state. `GraphicCommand`
stores captured bytes and selected Kitty metadata. `PaneGraphicsStore` owns
per-pane command history and image-id remapping. The core chooses positions and
re-emits graphics. The client forwards protocol bytes. Sixel and iTerm2 bytes
are not decoded into pixel resources.

## confirmed findings

### F-001

- severity: high
- class: protocol
- file: `src/pane/graphics.rs`, `GraphicsParser::handle_kitty_sequence`
- trigger: a Kitty `m=1` transfer is followed by a complete unrelated Kitty
  command before its final continuation
- impact: the unrelated command was appended to the incomplete image payload;
  the command was lost and the eventual final chunk could be emitted separately
- evidence: `interleaved_kitty_command_aborts_incomplete_transfer` failed before
  the fix because the captured command metadata was `a=T` instead of `a=d`
- fix: accept continuation headers only when they contain `m` and optional `q`;
  abort an unfinished transfer on another command and process that command
  independently; ignore orphan final chunks; preserve an active transfer across
  a feature query; accept a one-chunk transfer with explicit `m=0`
- status: fixed
- regression tests: `interleaved_kitty_command_aborts_incomplete_transfer`,
  `kitty_feature_query_does_not_abort_chunked_transfer`,
  `kitty_single_chunk_with_explicit_final_marker_is_emitted`

## open findings and release gaps

### F-002

- severity: high
- class: protocol
- file: `src/util/outer_term.rs`, `from_term_name`; `src/pane/query.rs`,
  `respond_kitty_query`
- summary: graphics support is inferred from terminal names and query replies
  claim Kitty features without a live host capability handshake
- trigger: a recognized terminal name or environment variable is present while
  the actual host, intermediary multiplexer, or requested feature does not
  support the claimed behavior
- impact: applications can select a graphics path that the host cannot display
- evidence: `from_term_name` maps names to broad protocol classes;
  `respond_kitty_query` answers `U=1` when only the broad Kitty bit is set
- fix: implement a capability snapshot based on a real client-side probe where
  the protocol permits one; keep conservative, explicit per-terminal support
  for capabilities that cannot be queried
- status: open

### F-003

- severity: medium
- class: terminal
- file: `src/pane/graphics.rs`, `handle_sixel_sequence`,
  `handle_iterm2_sequence`; `src/server/core.rs`, graphics emission
- summary: Sixel and iTerm2 data are forwarded as opaque sequences without a
  protocol-independent image and clipping model
- trigger: image output is scrolled, resized, clipped by a pane edge, or
  overlapped by another pane
- impact: image visibility and cleanup depend on host-specific terminal behavior
- evidence: Sixel stores an estimated size only; iTerm2 stores no parsed size;
  both keep the original sequence bytes and the client forwards them
- fix: add protocol adapters and lifecycle state that preserve the protocols'
  distinct positioning semantics, or document and expose narrower guarantees
- status: open

### F-004

- severity: medium
- class: test
- file: `tests/graphics_conformance_test.rs`
- summary: the integration tests prove capture and forwarding, not visible image
  correctness in a terminal
- trigger: rendering defects occur after the graphics bytes reach the client
- impact: automated tests can pass while image placement, clipping, scrolling,
  colors, or cleanup are visibly wrong
- evidence: assertions inspect `ScreenUpdate.gfx` and absence of payload text;
  no terminal grid or screenshot is compared; `kitten` and `chafa` cases skip if
  the executable is absent
- fix: add deterministic terminal-model tests and record actual-terminal checks
  separately from protocol forwarding tests
- status: open

### F-005

- severity: medium
- class: protocol
- file: `src/pane/graphics.rs`, `handle_iterm2_sequence`
- summary: OSC 1337 inline image parameters are not parsed into validated
  dimensions, cursor movement, or resource metadata
- trigger: an iTerm2 image uses width, height, percentage, inline, or filename
  parameters that affect its layout
- impact: venti cannot reliably preserve the application's image-to-content
  geometry across resize and scroll operations
- evidence: the handler stores the complete OSC bytes and sets `pixel_size` to
  `None`; no iTerm2 placement metadata is retained
- fix: parse and validate supported OSC 1337 fields and track its inline
  cursor-anchored extent without applying Kitty placement rules
- status: open

## executed verification

- `cargo test --all-targets`: passed, exit code 0
- `cargo test --test graphics_protocol_test`: passed, 24 tests
- `cargo fmt`: passed
- `cargo clippy --all-targets -- -D warnings`: passed
- `cargo fmt --check`: passed before the final graphics test additions; rerun
  during final verification

The protocol integration test does not prove real-terminal rendering. This
environment has not produced a compatibility matrix for Kitty, Ghostty,
WezTerm, foot, Konsole, iTerm2, tmux, or Zellij. No fuzz, sanitizer, soak, or
visual snapshot run is recorded here.

## release status

This audit is in progress. The code is not ready to label production-grade
0.2.0: F-002 through F-005 remain open, and the broader requirements for full
Kitty deletion/transfer semantics, Sixel lifecycle, real capability detection,
fuzzing, and terminal compatibility remain unverified.
